# Интеграционные контракты

Документ фиксирует границы интеграций до выбора конкретных SDK и провайдеров.

## InventoryProvider

Операции:
- получить доступный остаток по SKU;
- зарезервировать набор SKU на срок;
- подтвердить списание после успешной оплаты;
- освободить резерв;
- синхронизировать остатки из внешнего источника.

Реализация на старте — локальная БД. Внешняя 1С/МойСклад подключается отдельным адаптером. Важно определить единственный источник истины, чтобы не допустить двойного списания.

## PaymentProvider

Операции:
- создать платёж с уникальным idempotency key;
- получить актуальный статус платежа;
- обработать входящее уведомление;
- инициировать полный/частичный возврат.

Внутренняя модель должна различать как минимум pending, requires_review, authorized, paid, failed, cancelled, refunded и partially_refunded. Фактические статусы внешнего провайдера маппятся в эту модель.

## ShippingProvider

Операции:
- рассчитать доступные способы и стоимость;
- вернуть доступные ПВЗ/слоты;
- создать отправление;
- получить этикетку или QR/код передачи;
- отменить отправление;
- получить статус доставки.

Каждый адаптер документирует ограничения API, доступные страны/регионы, типы отправления и требования к договору/тарифу.

## Webhook policy

- Проверять подпись и подлинность события.
- Сохранять входящее событие до обработки.
- Обеспечить уникальность provider + event id.
- Обрабатывать событие в очереди.
- Повторная доставка события не должна повторять бизнес-операцию.
- При конфликтующих/пропущенных событиях сверяться с API провайдера.
